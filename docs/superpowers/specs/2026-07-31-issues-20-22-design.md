# Issues #20 and #22 Resolution Design

**Status:** Approved

## Context

[Issue #20](https://github.com/lmilojevicc/herdr-splits.nvim/issues/20) reports that the lazy.nvim `build` examples are interpreted as shell commands. lazy.nvim treats strings beginning with `:` as Neovim commands; without that prefix, Zsh attempts to parse `lua require(...)` and fails.

[Issue #22](https://github.com/lmilojevicc/herdr-splits.nvim/issues/22) reports that `sync_herdr()` silently ignores Herdr 0.7.5 plugin-list output. Herdr returns an envelope whose plugin entries are under `result.plugins`, while the current code only accepts a top-level array or bare plugin object. The outer envelope has no `source`, so synchronization exits without comparing or updating commits.

The current synchronization strategy remains valid: Herdr has no separate plugin-update operation, so reinstalling the plugin with an exact `--ref` is the supported way to make the Herdr-managed scripts match the lazy.nvim checkout.

## Goals

- Make both documented lazy.nvim build hooks invoke `sync_herdr()` as Neovim commands.
- Accept Herdr 0.7.5's `result.plugins` response envelope.
- Preserve compatibility with top-level plugin arrays and bare plugin objects.
- Select the target plugin by exact `plugin_id` in list-shaped responses.
- Preserve the existing best-effort update lifecycle and failure behavior.
- Add focused regression coverage for synchronization decisions and subprocess calls.

## Non-goals

This change will not add locking, retries, asynchronous execution, post-install verification, new notifications, or a broader update lifecycle. It will not change the hard-coded upstream source, define new fork behavior, require `result.type`, or consolidate plugin-management parsing into `herdr.lua`.

## Design

### lazy.nvim build hooks

Both lazy.nvim examples in `README.md` will use:

```lua
build = ':lua require("herdr-splits").sync_herdr()'
```

The leading colon makes lazy.nvim dispatch the string as an Ex command instead of a shell command. A Lua callback would also work, but the colon-prefixed string is the narrow correction requested by issue #20.

### Plugin-entry selection

`lua/herdr-splits/sync.lua` will gain one private local selector. It will not be exported or moved into another module.

The selector will apply these rules in order:

1. Type-check the decoded top-level value and every nested field before indexing it; malformed values must return `nil` without throwing.
2. When the top-level table has an envelope marker (`id` or `result`), treat it as an envelope. Use `result.plugins` only when both `result` and `plugins` are tables. If `result` or `plugins` is missing or fails its type check, return `nil` rather than falling through to the bare-object fallback.
3. Otherwise, if the decoded top-level value is list-shaped, use it as the legacy list container.
4. Otherwise, treat the decoded top-level table as the legacy bare plugin object.
5. Search list containers for a table whose `plugin_id` is exactly `herdr-splits`; skip non-table or unrelated members.
6. Return `nil` when a list contains no matching entry. An empty envelope therefore remains a no-op rather than falling through to the outer response object.

The bare-object fallback applies only to genuinely top-level plugin objects and preserves the existing behavior: downstream validation decides whether their `source` is usable.

### Synchronization data flow

The rest of `sync()` remains unchanged:

1. Return unless `auto_sync_herdr` is enabled.
2. Resolve the Herdr executable and the Neovim plugin checkout.
3. Read the lazy.nvim checkout commit with `git rev-parse HEAD`.
4. Request `herdr plugin list --plugin herdr-splits --json`.
5. Decode the response and select the plugin entry using the private selector.
6. Return unless the selected source is a GitHub source.
7. Compare the managed and lazy commits case-insensitively.
8. When they differ, run:

   ```text
   herdr plugin install lmilojevicc/herdr-splits.nvim --ref <lazy-sha> --yes
   ```

The hard-coded source, synchronous subprocess model, success notification, and install-failure notification remain unchanged.

### Update convergence

The lazy.nvim build hook and setup-time synchronization remain complementary triggers. A build hook may run before plugin configuration enables `auto_sync_herdr`, in which case it is a no-op. When setup later enables synchronization, the setup-time invocation compares the checkouts and repairs any mismatch. Together these triggers provide best-effort eventual convergence without adding lifecycle state or background work.

## Failure Behavior

Malformed JSON, non-table decoded values, missing or non-table envelope fields, malformed list members, empty plugin lists, and missing target entries remain silent no-ops. The selector handles these shapes without throwing, so they do not reach the outer error notification path. Missing executables, failed list or commit commands, local-link/non-GitHub sources, and already matching commits also retain their current behavior. Existing notifications after an attempted install are unchanged.

The outer `pcall` continues to prevent synchronization failures from disrupting plugin setup.

## Testing

Add `tests/test_sync.lua` using the repository's MiniTest child-Neovim and queued `vim.system` mocking patterns. Coverage will include:

1. A stale target in `result.plugins` triggers the exact pinned install command.
2. An unrelated entry before the target proves selection by `plugin_id`.
3. Matching commits, including case-only differences, do not reinstall.
4. Bare plugin objects and top-level plugin arrays remain supported.
5. Empty or malformed envelopes, missing targets, and non-GitHub sources do not install.
6. Disabled `auto_sync_herdr` performs no subprocess work.

Run `make check` as the implementation validation command. The documentation change is accepted when both lazy.nvim build examples contain the exact colon-prefixed command.

## Acceptance Criteria

- Both README build-hook examples use `:lua require("herdr-splits").sync_herdr()`.
- Herdr 0.7.5 envelope output selects the `herdr-splits` entry and installs the lazy checkout commit when stale.
- List responses never assume the target is the first entry.
- Legacy bare-object and bare-array responses retain working behavior.
- Matching commits and all documented no-op cases do not issue an install command.
- Existing source handling, comparison, install command, notifications, and best-effort semantics do not change.
- `make check` passes.

## Residual Risks

The following risks predate these fixes and are intentionally deferred:

- Concurrent Neovim processes can observe the same stale commit and attempt simultaneous installs.
- A GitHub fork using the same plugin ID can be replaced by the hard-coded upstream source.
- A successful install is trusted without re-listing and verifying the resulting commit.
- Build-time synchronization may run before configuration, relying on setup-time synchronization for convergence.
